# chaos-lab 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 `chaoslab` 单二进制：按插件协议编排故障演练场景，起环境、只给现象、用户自己修、`check` 判定通过并写 run 记录、`stop` 后证明零残留。

**Architecture:** Go 命令行程序，纯编排器。插件是 `~/.lab/plugins/<name>/plugin` 的可执行文件，框架通过 5 个子命令（`list` / `schema` / `up` / `down` / `check`）一次性子进程调用，零长驻进程。所有环境创建与清理由插件负责，框架负责参数校验、claims 冲突检测、超时与进程组终止、状态持久化、退出后 claims 实测复查。

**Tech Stack:** Go 1.22+（仅标准库：`os/exec`、`encoding/json`、`flag` 或手写 argv 解析、`syscall.Flock`、`sync`）。测试用 `testing` + 内嵌 shell 假插件。V1 k8s 插件用 bash + kind + kubectl。

**Spec:** `docs/superpowers/specs/2026-11-20-chaos-lab-design.md`

## Global Constraints

- 二进制名 `chaoslab`，Go 单二进制，不引入第三方依赖（`go.mod` 无 require）
- 本地状态唯一位置 `~/.lab/`（`plugins/`、`state/`、`runs/`）；测试通过 `CHAOSLAB_HOME` 环境变量重定向，禁止测试写入真实 `~/.lab`
- 框架不创建、不删除任何环境资源；不重试失败的 `down`
- 插件内部结构零假设：只要求 `<plugindir>/plugin` 存在且可执行
- 所有子进程超时到达时对**进程组** `SIGTERM`，5 秒后 `SIGKILL`
- 退出码：`0` 成功/通过，`1` 用户错误，`2` 未通过，`3` 插件执行出错
- 协议 stdout 只放 JSON，stderr 只放人类文案；框架把 stderr 实时透传
- 插件子进程 stdin 接 `/dev/null`，cwd 为插件目录，环境含 `LAB_INSTANCE`、`LAB_PLUGIN_DIR`、`LAB_CASE`

## Review Focus

每条都要在对应任务里有测试：

1. **`~/.lab/state/instances.json` 损坏或被手工改成非法 JSON** —— 用户会手改这个文件。期望：报错并指出文件路径，不要静默重置丢失活跃实例（否则真实环境变孤儿）。→ Task 4
2. **框架在 `up` 期间被 `kill -9`** —— 留下 `starting` 记录。期望：任何后续命令惰性收敛为 `stopped`/`live=true`/中断原因，`stop` 能收尾。→ Task 7
3. **插件 `check` 挂住不返回** —— 期望：2 分钟后被杀，提示检查超时，退出码 3，不计入 `checks`。→ Task 8
4. **插件输出垃圾**（`list` 返回非 JSON、`check` 退出码 0 但 stdout 为空、schema 里 `type` 是未知值）—— 期望：明确报协议错误，退出码 3，不写入状态。→ Task 5、Task 8
5. **`stop` 时 claims 没释放干净 / 无法判断**（`kind` 命令不存在导致复查失败）—— 期望：标 `dirty` 并保留 `live=true`，不能因为无法验证就当作已清理。→ Task 6
